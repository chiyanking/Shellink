# 会话管理设计

会话管理页面汇总 Desktop 和 MCP 创建的终端实例，包括未在工作台打开的活跃会话和已经结束的会话。连接配置、会话进程、历史记录和控制权都由同一个 Rust Desktop 核心维护。

## 管理入口

左侧「会话管理」使用快捷键 `Cmd/Ctrl+2` 打开。连接管理负责保存主机、认证和启动命令配置；工作台负责当前打开的终端视图；历史记录按 session 展示输入、输出和结束信息。

一个连接可以有多个会话，例如同一主机同时用于巡检和部署日志。每个会话拥有独立 ID、终端进程、控制模式和生命周期，收起标签只移除视图，不会结束进程。

## 页面行为

- 列表支持活跃、待接管、已结束和全部视图，并可按 Desktop 或 MCP 创建来源筛选。
- 每行显示会话名称、连接名称、ID、状态、来源、控制模式和最近活动。
- 详情侧栏展示目标地址、创建时间、会话时长、工作台可见性和最近历史。
- 活跃会话可以打开、重命名、切换 `AUTO` / `MANUAL`，或结束并保留历史。
- 已结束会话只提供记录查看，不显示可继续输入的终端入口。

创建来源和当前控制权分开展示：来源描述会话由 Desktop 还是 MCP 创建，`AUTO` / `MANUAL` 描述当前允许谁写入终端。

## 生命周期

新建会话会启动本地 command 或 SSH 子进程并写入 SQLite。输出实时发布到 Tauri 事件总线，同时按 seq 保存到历史。关闭会话会终止子进程、清理临时 SSH 私钥并记录结束原因；关闭 Desktop 时所有活动会话都会执行同样的清理。

## 历史与回调

历史页可按 session 查询、分页和导出终端片段。Webhook 回调单独显示在 AI 接入页面，回调消息携带 `sessionId` 时可以跳转到对应会话；清空回调消息不会影响终端历史。
